# 15 全栈项目实战

> 用 Django 5.2 + DRF + Redis + Celery + Vue3 + Nginx + Docker 构建电商秒杀 + 排行榜 + Feed 流全栈项目，覆盖架构、库存预扣、分布式锁、异步订单、限流、SSE 实时推送、容器化部署与生产 Checklist。

## 零基础前置认知

**这篇在讲什么**：把前面各篇的"零件"（Lua 库存、分布式锁、Stream 消费组、ZSet 排行榜、缓存预热）**拧成一台能跑的电商秒杀整机**——Django+DRF 做 API、Redis Lua 预扣库存防超卖、SET NX EX+看门狗防重复下单、Celery+Stream 异步处理订单、SSE 实时推排行榜。读完你能看懂一张完整的秒杀架构图，并照着把 `docker-compose.yml` 拉起一整套前后端+中间件。*本篇是验收章：所有命令/配置以可运行为准，前端 Vue3+Vite 5 按官方最新稳定标注。（配套技术点均可回查对应章节：Lua→07、锁→10、Stream→08。）*

> 辅助类比：把秒杀系统想成"双十一抢购一条龙"——**库存预扣** 是"拍下即锁 1 件库存，付款才真扣"（Lua 保证不超卖：两个人都拍最后一件，只有一人成功）；**分布式锁** 是"防重复下单：每人一个订单号只能提交一次"（门禁）；**异步订单** 是"拍下后立刻告诉你成功、后台慢慢处理"（Stream 消费组：前端秒回、后端排队）；**排行榜** 是"实时比分墙"（ZSet score=积分秒刷）；**SSE** 是"直播间单向广播"（服务端→浏览器实时推送，不用轮询）。

## 学习目标

1. 能够绘制并解读电商秒杀系统的端到端架构，理解各组件职责。

4. 能够用 Celery + Redis Stream 消费者组实现异步订单处理与可靠消费。
5. 能够用 ZSet 实现实时积分排行榜，用推/拉模式实现 Feed 流。
6. 能够用 Vue3 + Pinia + SSE 实现秒杀前端页面与实时排行榜。
7. 能够编写完整 `docker-compose.yml`（Django + Redis + MySQL + Celery + Nginx + 监控栈）。
8. 能够识别热点 key、缓存预热、Pipeline 等性能优化点，避开常见踩坑。

## 一、项目总览

### 1.1 业务场景

- **秒杀模块**：100 件商品，10 万人抢购，要求不超卖、不漏单、低延迟。
- **排行榜模块**：实时积分排行，毫秒级更新，支持 Top N 与"我附近的玩家"。
- **Feed 流模块**：好友动态推拉结合，普通用户推、大 V 拉。
- **会话管理**：JWT + Redis Session，支持双端登录控制。
- **监控告警**：Prometheus + Grafana 全链路监控。

### 3.2 Lua 脚本（库存预扣 + 锁释放 + 限流）

`apps/seckill/lua_scripts.py`：

```python
# apps/seckill/lua_scripts.py

# 库存预扣：原子检查 + DECR，防止超卖
# KEYS[1] = stock key
# ARGV[1] = user id (用于已购买集合去重)
# ARGV[2] = bought set key
# 返回：1 成功，0 库存不足，-1 已购买
DEDUCT_STOCK_LUA = """
local stock_key = KEYS[1]
local bought_key = KEYS[2]
local user_id = ARGV[1]

-- 已购买集合检查
if redis.call('SISMEMBER', bought_key, user_id) == 1 then
    return -1
end

local stock = tonumber(redis.call('GET', stock_key) or 0)
if stock <= 0 then
    return 0
end

-- 原子扣减
redis.call('DECR', stock_key)
redis.call('SADD', bought_key, user_id)
return 1
"""

# 分布式锁释放：检查 owner 才删除
# KEYS[1] = lock key
# ARGV[1] = identifier
UNLOCK_LUA = """
if redis.call('GET', KEYS[1]) == ARGV[1] then
    return redis.call('DEL', KEYS[1])
end
return 0
"""

# 锁续期：看门狗
RENEW_LUA = """
if redis.call('GET', KEYS[1]) == ARGV[1] then
    return redis.call('EXPIRE', KEYS[1], ARGV[2])
end
return 0
"""

# 令牌桶限流
# KEYS[1] = bucket key
# ARGV[1] = capacity
# ARGV[2] = rate (tokens/ms)
# ARGV[3] = now (ms)
# ARGV[4] = requested tokens
TOKEN_BUCKET_LUA = """
local key = KEYS[1]
local capacity = tonumber(ARGV[1])
local rate = tonumber(ARGV[2])
local now = tonumber(ARGV[3])
local requested = tonumber(ARGV[4])

local info = redis.call('HMGET', key, 'tokens', 'last_time')
local tokens = tonumber(info[1]) or capacity
local last_time = tonumber(info[2]) or now

local elapsed = math.max(0, now - last_time)
tokens = math.min(capacity, tokens + elapsed * rate)

local allowed = 0
if tokens >= requested then
    tokens = tokens - requested
    allowed = 1
end
redis.call('HSET', key, 'tokens', tokens, 'last_time', now)
redis.call('PEXPIRE', key, math.ceil(capacity / rate) + 10000)
return allowed
"""

# 滑动窗口限流
# KEYS[1] = zset key
# ARGV[1] = window_ms
# ARGV[2] = limit
# ARGV[3] = now (ms)
# ARGV[4] = member
SLIDING_WINDOW_LUA = """
local key = KEYS[1]
local window = tonumber(ARGV[1])
local limit = tonumber(ARGV[2])
local now = tonumber(ARGV[3])
local member = ARGV[4]

redis.call('ZREMRANGEBYSCORE', key, 0, now - window)
local count = redis.call('ZCARD', key)
if count < limit then
    redis.call('ZADD', key, now, member)
    redis.call('PEXPIRE', key, window)
    return 1
end
return 0
"""
```

### 3.3 限流器

`apps/common/throttles.py`：

```python
# apps/common/throttles.py
import time

from rest_framework.throttling import BaseThrottle

from apps.common.redis_client import get_redis
from apps.seckill.lua_scripts import TOKEN_BUCKET_LUA, SLIDING_WINDOW_LUA


class TokenBucketThrottle(BaseThrottle):
    """令牌桶限流：允许突发，平滑限流"""

    capacity = 100         # 桶容量
    rate_per_sec = 50      # 每秒填充令牌数

    def get_cache_key(self, request, view):
        if request.user and request.user.is_authenticated:
            return f"throttle:bucket:{request.user.id}"
        return f"throttle:bucket:ip:{self.get_ident(request)}"

    def allow_request(self, request, view):
        key = self.get_cache_key(request, view)
        r = get_redis()
        now = int(time.time() * 1000)
        try:
            result = r.eval(
                TOKEN_BUCKET_LUA, 1, key,
                self.capacity, self.rate_per_sec / 1000.0, now, 1
            )
            return int(result) == 1
        except Exception:
            # Redis 故障时降级放行（业务可接受）
            return True

    def wait(self):
        return 1.0 / self.rate_per_sec


class SlidingWindowThrottle(BaseThrottle):
    """滑动窗口限流：精确控制窗口内请求数"""

    window_ms = 60_000      # 1 分钟
    limit = 100              # 窗口内最大请求

    def get_cache_key(self, request, view):
        if request.user and request.user.is_authenticated:
            return f"throttle:window:{request.user.id}"
        return f"throttle:window:ip:{self.get_ident(request)}"

    def allow_request(self, request, view):
        key = self.get_cache_key(request, view)
        r = get_redis()
        now = int(time.time() * 1000)
        member = f"{now}:{request.user.id if request.user.is_authenticated else 'anon'}"
        try:
            result = r.eval(
                SLIDING_WINDOW_LUA, 1, key,
                self.window_ms, self.limit, now, member
            )
            return int(result) == 1
        except Exception:
            return True

    def wait(self):
        return self.window_ms / 1000
```

### 3.4 分布式锁

`apps/common/locks.py`：

```python
# apps/common/locks.py
import threading
import time
import uuid

from apps.common.redis_client import get_redis
from apps.seckill.lua_scripts import UNLOCK_LUA, RENEW_LUA


class DistributedLock:
    """SET NX EX + Lua 释放 + 看门狗续期"""

    def __init__(self, lock_key: str, timeout: int = 30,
                 retry_times: int = 3, retry_delay: float = 0.1,
                 watchdog: bool = True):
        self.lock_key = f"lock:{lock_key}"
        self.timeout = timeout
        self.retry_times = retry_times
        self.retry_delay = retry_delay
        self.watchdog = watchdog
        self.identifier = str(uuid.uuid4())
        self._timer = None
        self._client = None
        self._thread_local = threading.local()

    def _get_client(self):
        if not getattr(self._thread_local, "client", None):
            self._thread_local.client = get_redis()
        return self._thread_local.client

    def __enter__(self):
        client = self._get_client()
        for _ in range(self.retry_times):
            ok = client.set(self.lock_key, self.identifier, ex=self.timeout, nx=True)
            if ok:
                if self.watchdog:
                    self._start_renewal()
                return self
            time.sleep(self.retry_delay)
        raise TimeoutError(f"acquire lock {self.lock_key} timeout")

    def __exit__(self, exc_type, exc_val, exc_tb):
        self._stop_renewal()
        client = self._get_client()
        try:
            client.eval(UNLOCK_LUA, 1, self.lock_key, self.identifier)
        except Exception:
            pass
        return False

    def _start_renewal(self):
        interval = self.timeout / 3

        def renew():
            while self._timer is not None:
                try:
                    client = self._get_client()
                    client.eval(RENEW_LUA, 1, self.lock_key, self.identifier, self.timeout)
                except Exception:
                    pass
                time.sleep(interval)

        self._timer = threading.Thread(target=renew, daemon=True)
        self._timer.start()

    def _stop_renewal(self):
        self._timer = None
```

```python
# apps/seckill/services.py
import json
import logging
import time
import uuid

from django.core.cache import cache
from django.utils import timezone

from apps.common.redis_client import get_redis
from apps.seckill.lua_scripts import DEDUCT_STOCK_LUA

logger = logging.getLogger(__name__)

STREAM_NAME = "seckill:orders"
GROUP_NAME = "order_workers"


class SeckillService:
    """秒杀核心服务：库存预扣 + 去重 + 异步下单"""

    def __init__(self, redis_client=None):
        self.r = redis_client or get_redis()

    def stock_key(self, product_id: int) -> str:
        return f"seckill:stock:{product_id}"

    def bought_key(self, product_id: int) -> str:
        return f"seckill:bought:{product_id}"

    def preheat(self, product_id: int, stock: int):
        """秒杀开始前预热库存到 Redis"""
        self.r.set(self.stock_key(product_id), stock)
        self.r.delete(self.bought_key(product_id))
        logger.info("preheat stock %s = %s", product_id, stock)

    def try_kill(self, product_id: int, user_id: int) -> dict:
        """
        秒杀请求核心逻辑：
        1. Lua 原子扣库存 + 去重
        2. 成功则 XADD 推送到 Stream，由 Celery 异步处理
        3. 返回排队号，前端通过 SSE 查询结果
        """
        # 1) Lua 原子扣库存
        result = self.r.eval(
            DEDUCT_STOCK_LUA, 2,
            self.stock_key(product_id),
            self.bought_key(product_id),
            str(user_id),
        )
        result = int(result)
        if result == -1:
            return {"success": False, "code": "ALREADY_BOUGHT", "message": "您已抢购过该商品"}
        if result == 0:
            return {"success": False, "code": "OUT_OF_STOCK", "message": "已抢完"}

        # 2) 推送 Stream（异步处理）
        ticket = str(uuid.uuid4())
        fields = {
            "product_id": str(product_id),
            "user_id": str(user_id),
            "ticket": ticket,
            "ts": str(int(time.time() * 1000)),
        }
        msg_id = self.r.xadd(STREAM_NAME, fields, maxlen=100_000, approximate=True)

        # 3) 立即返回排队号
        return {
            "success": True,
            "code": "QUEUED",
            "ticket": ticket,
            "message": "排队中，请等待结果",
            "stream_id": msg_id,
        }

    def query_result(self, ticket: str) -> dict:
        """前端轮询/SSE 查询订单结果"""
        # 结果存于 Redis Hash，由 Celery worker 写入
        data = self.r.hgetall(f"seckill:result:{ticket}")
        if not data:
            return {"status": "pending"}
        return {
            "status": data.get("status", "pending"),
            "order_no": data.get("order_no"),
            "message": data.get("message", ""),
        }

    def get_remaining_stock(self, product_id: int) -> int:
        stock = self.r.get(self.stock_key(product_id))
        return int(stock) if stock else 0
```

```python
# apps/orders/tasks.py
import json
import logging
import uuid

import redis
from celery import shared_task
from celery.exceptions import SoftTimeLimitExceeded
from django.db import transaction
from django.utils import timezone

from apps.common.redis_client import get_redis
from apps.seckill.services import STREAM_NAME, GROUP_NAME

logger = logging.getLogger(__name__)


def ensure_group():
    r = get_redis()
    try:
        r.xgroup_create(STREAM_NAME, GROUP_NAME, id="0", mkstream=True)
    except redis.ResponseError as e:
        if "BUSYGROUP" not in str(e):
            raise


@shared_task(bind=True, autoretry_for=(Exception,), max_retries=3, retry_backoff=True)
def consume_seckill_stream(self, count: int = 10, block_ms: int = 5000):
    """消费秒杀 Stream，创建订单"""
    ensure_group()
    r = get_redis()
    consumer = f"worker-{self.request.hostname}"
    messages = r.xreadgroup(
        GROUP_NAME, consumer, {STREAM_NAME: ">"},
        count=count, block=block_ms,
    )
    processed = 0
    for _stream, msgs in messages:
        for msg_id, fields in msgs:
            try:
                _process_one(fields)
                r.xack(STREAM_NAME, GROUP_NAME, msg_id)
                processed += 1
            except SoftTimeLimitExceeded:
                logger.warning("soft timeout on %s", msg_id)
                raise
            except Exception as exc:
                logger.exception("process %s failed: %s", msg_id, exc)
                # 不 ACK，等待 XCLAIM 重新分配
    return processed


def _process_one(fields: dict):
    """实际订单创建逻辑"""
    from apps.orders.models import Order
    from apps.products.models import Product
    from apps.users.models import User

    product_id = int(fields["product_id"])
    user_id = int(fields["user_id"])
    ticket = fields["ticket"]

    with transaction.atomic():
        product = Product.objects.select_for_update().get(pk=product_id)
        user = User.objects.get(pk=user_id)

        if product.stock < 1:
            _notify_result(ticket, "failed", message="库存不足")
            return

        # 扣 DB 库存
        product.stock -= 1
        product.sales_count += 1
        product.save(update_fields=["stock", "sales_count", "updated_at"])

        # 创建订单
        order = Order.objects.create(
            user=user,
            product=product,
            quantity=1,
            unit_price=product.seckill_price or product.price,
            total_amount=product.seckill_price or product.price,
            status=Order.Status.PENDING,
        )

    # 写入结果，前端 SSE 读取
    _notify_result(
        ticket, "success",
        order_no=str(order.order_no),
        message="秒杀成功，请在 15 分钟内支付",
    )

    # 投递延迟任务：15 分钟未支付自动取消
    cancel_order.apply_async(args=[order.id], countdown=15 * 60)


def _notify_result(ticket: str, status_str: str, **extra):
    """通过 Redis Hash 存结果 + Pub/Sub 通知 SSE"""
    r = get_redis()
    payload = {"status": status_str, **{k: str(v) for k, v in extra.items()}}
    r.hset(f"seckill:result:{ticket}", mapping=payload)
    r.expire(f"seckill:result:{ticket}", 3600)
    r.publish(f"seckill:notify:{ticket}", json.dumps(payload))


@shared_task(bind=True, max_retries=3)
def cancel_order(self, order_id: int):
    """订单超时自动取消，回滚库存"""
    from apps.orders.models import Order
    from apps.products.models import Product
    from apps.seckill.services import SeckillService

    with transaction.atomic():
        order = Order.objects.select_for_update().get(pk=order_id)
        if order.status != Order.Status.PENDING:
            return  # 已支付或已取消

        order.status = Order.Status.TIMEOUT
        order.save(update_fields=["status", "updated_at"])

        product = Product.objects.select_for_update().get(pk=order.product_id)
        product.stock += 1
        product.sales_count = max(0, product.sales_count - 1)
        product.save(update_fields=["stock", "sales_count", "updated_at"])

    # 回滚 Redis 库存与已购买集合
    service = SeckillService()
    r = get_redis()
    r.incr(service.stock_key(order.product_id))
    r.srem(service.bought_key(order.product_id), str(order.user_id))
    logger.info("order %s cancelled, stock restored", order_id)


@shared_task
def reclaim_stale_messages(min_idle_ms: int = 60_000, count: int = 20):
    """回收超时未 ACK 的 Stream 消息"""
    r = get_redis()
    consumer = "reclaimer"
    pending = r.xpending_range(STREAM_NAME, GROUP_NAME, "-", "+", count)
    reclaimed = 0
    for p in pending:
        if p.get("time_since_delivered", 0) > min_idle_ms:
            claimed = r.xclaim(
                STREAM_NAME, GROUP_NAME, consumer, min_idle_ms, [p["message_id"]]
            )
            reclaimed += len(claimed)
    return reclaimed
```

```python
from typing import Optional

from apps.common.redis_client import get_redis


class LeaderboardService:
    """基于 ZSet 的实时积分排行榜"""

    KEY = "leaderboard:points"
    KEY_DAILY = "leaderboard:points:daily:{date}"

    def __init__(self, redis_client=None):
        self.r = redis_client or get_redis()

    def add_or_update(self, user_id: int, score: float, daily: bool = False):
        """设置用户分数（覆盖）"""
        key = self._key(daily)
        self.r.zadd(key, {str(user_id): score})

    def incr_score(self, user_id: int, delta: float, daily: bool = False) -> float:
        """增量调整分数"""
        key = self._key(daily)
        return float(self.r.zincrby(key, delta, str(user_id)))

    def get_top(self, count: int = 10, daily: bool = False) -> list[dict]:
        """获取 Top N（降序）"""
        key = self._key(daily)
        results = self.r.zrevrange(key, 0, count - 1, withscores=True)
        return [{"user_id": int(uid), "score": float(score)} for uid, score in results]

    def get_rank(self, user_id: int, daily: bool = False) -> Optional[int]:
        """获取用户排名（1-based，降序）"""
        key = self._key(daily)
        rank = self.r.zrevrank(key, str(user_id))
        return rank + 1 if rank is not None else None

    def get_score(self, user_id: int, daily: bool = False) -> Optional[float]:
        key = self._key(daily)
        score = self.r.zscore(key, str(user_id))
        return float(score) if score is not None else None

    def get_around(self, user_id: int, count: int = 5, daily: bool = False) -> list[dict]:
        """获取用户附近 N 名玩家"""
        key = self._key(daily)
        rank = self.r.zrevrank(key, str(user_id))
        if rank is None:
            return []
        start = max(0, rank - count)
        end = rank + count
        results = self.r.zrevrange(key, start, end, withscores=True)
        return [{"user_id": int(uid), "score": float(score)} for uid, score in results]

    def _key(self, daily: bool) -> str:
        if daily:
            from django.utils import timezone
            return self.KEY_DAILY.format(date=timezone.now().date().isoformat())
        return self.KEY
```

```python
# apps/feed/services.py
import time
import logging

from django.utils import timezone

from apps.common.redis_client import get_redis

logger = logging.getLogger(__name__)


class FeedService:
    """推拉结合 Feed 流：普通用户推、大 V 拉"""

    BIG_V_THRESHOLD = 1000  # 粉丝数超过此值视为大 V
    TIMELINE_LIMIT = 1000   # 收件箱保留条数

    def __init__(self, redis_client=None):
        self.r = redis_client or get_redis()

    def _inbox_key(self, user_id: int) -> str:
        return f"feed:inbox:{user_id}"

    def _outbox_key(self, user_id: int) -> str:
        return f"feed:outbox:{user_id}"

    def publish_post(self, author_id: int, post_id: int):
        """发布动态：大 V 写 outbox，普通用户推到粉丝 inbox"""
        from apps.feed.models import Follow
        ts = int(time.time() * 1000)

        # 写自己的 outbox（拉模式需要）
        self.r.zadd(self._outbox_key(author_id), {str(post_id): ts})

        # 计算粉丝数
        fan_count = Follow.objects.filter(followee_id=author_id).count()

        if fan_count > self.BIG_V_THRESHOLD:
            # 大 V：仅写 outbox，不推
            logger.info("big-v post %s, fan=%s, skip push", post_id, fan_count)
            return

        # 普通用户：写扩散到所有粉丝 inbox
        follower_ids = Follow.objects.filter(
            followee_id=author_id
        ).values_list("follower_id", flat=True)

        if not follower_ids:
            return

        # Pipeline 批量推送
        pipeline = self.r.pipeline()
        for fid in follower_ids:
            pipeline.zadd(self._inbox_key(fid), {str(post_id): ts})
            pipeline.zremrangebyrank(
                self._inbox_key(fid), 0, -self.TIMELINE_LIMIT - 1
            )
        pipeline.execute()

    def get_timeline(self, user_id: int, page: int = 1, size: int = 20) -> list[int]:
        """
        获取 Feed 流：
        - 自己的 inbox（普通用户被推送的）
        - 关注的大 V 的 outbox（拉模式合并）
        """
        from apps.feed.models import Follow

        inbox_key = self._inbox_key(user_id)
        start = (page - 1) * size
        end = start + size - 1

        # 1) 自己 inbox 中已有的
        post_ids = self.r.zrevrange(inbox_key, start, end)
        if not post_ids:
            post_ids = []

        # 2) 拉取关注的大 V 的 outbox（合并）
        big_v_ids = Follow.objects.filter(
            follower_id=user_id, followee__followers__gte__=0  # 实际查粉丝数
        ).values_list("followee_id", flat=True)

        # 简化版：合并所有关注者的 outbox
        following_ids = Follow.objects.filter(
            follower_id=user_id
        ).values_list("followee_id", flat=True)

        if following_ids:
            # 临时合并到 zset
            tmp_key = f"feed:tmp:{user_id}"
            keys = [self._outbox_key(fid) for fid in following_ids]
            keys.append(inbox_key)
            self.r.zunionstore(tmp_key, keys)
            self.r.expire(tmp_key, 60)
            post_ids = self.r.zrevrange(tmp_key, start, end)

        return [int(pid) for pid in post_ids]

    def unfollow(self, follower_id: int, followee_id: int):
        """取关：清理 inbox 中来自对方的动态"""
        # 1. 取出对方 outbox 中的全部动态 ID
        post_ids = self.r.zrange(self._outbox_key(followee_id), 0, -1)
        if not post_ids:
            return
        # 2. 从自己的 inbox 中批量移除这些动态
        self.r.zrem(self._inbox_key(follower_id), *post_ids)

    def delete_post(self, author_id: int, post_id: int):
        """删除动态：从 outbox + 所有 inbox 中移除"""
        self.r.zrem(self._outbox_key(author_id), str(post_id))
        # inbox 清理需要扫描所有用户，成本高，通常异步处理
```

```python
from rest_framework.permissions import AllowAny, IsAuthenticated
from rest_framework.response import Response
from rest_framework.views import APIView
from rest_framework_simplejwt.serializers import TokenObtainPairSerializer
from rest_framework_simplejwt.views import TokenObtainPairView

from apps.common.redis_client import get_redis

SESSION_PREFIX = "sess:"
SESSION_LIST_PREFIX = "sess:list:"
MAX_SESSIONS = 3


class LoginView(TokenObtainPairView):
    """登录：JWT + Redis Session + 双端控制"""

    def post(self, request, *args, **kwargs):
        response = super().post(request, *args, **kwargs)
        if response.status_code == 200:
            user_id = request.data.get("username")
            # 简化版：实际应从 JWT payload 中解析
            from django.contrib.auth import get_user_model
            User = get_user_model()
            try:
                user = User.objects.get(username=user_id)
                sid = str(uuid.uuid4())
                r = get_redis()
                r.set(
                    f"{SESSION_PREFIX}{sid}",
                    f"{user.id}:{user.username}",
                    ex=settings.SESSION_COOKIE_AGE,
                )
                # 维护用户的会话列表（双端控制）
                list_key = f"{SESSION_LIST_PREFIX}{user.id}"
                r.lpush(list_key, sid)
                r.ltrim(list_key, 0, MAX_SESSIONS - 1)
                r.expire(list_key, settings.SESSION_COOKIE_AGE)
                # 淘汰旧会话
                all_sids = r.lrange(list_key, 0, -1)
                if len(all_sids) > MAX_SESSIONS:
                    for old_sid in all_sids[MAX_SESSIONS:]:
                        r.delete(f"{SESSION_PREFIX}{old_sid}")
                response.data["session_id"] = sid
            except User.DoesNotExist:
                pass
        return response


class LogoutView(APIView):
    permission_classes = [IsAuthenticated]

    def post(self, request):
        sid = request.META.get("HTTP_X_SESSION_ID")
        if sid:
            r = get_redis()
            r.delete(f"{SESSION_PREFIX}{sid}")
            if request.user.is_authenticated:
                r.lrem(f"{SESSION_LIST_PREFIX}{request.user.id}", 1, sid)
        return Response(status=204)
```

```typescript
import { defineStore } from 'pinia'
import { ref } from 'vue'
import axios from 'axios'

export interface SeckillResult {
  success: boolean
  code: string
  ticket?: string
  message: string
}

export const useSeckillStore = defineStore('seckill', () => {
  const productId = ref<number>(0)
  const remainingStock = ref<number>(0)
  const loading = ref(false)
  const result = ref<SeckillResult | null>(null)
  const orderNo = ref<string>('')

  async function fetchProduct(id: number) {
    const res = await axios.get(`/api/seckill/products/${id}/`)
    productId.value = res.data.id
    remainingStock.value = res.data.remaining_stock
  }

  async function execute() {
    loading.value = true
    try {
      const res = await axios.post(`/api/seckill/products/${productId.value}/execute/`)
      result.value = res.data
      if (res.data.ticket) {
        remainingStock.value = Math.max(0, remainingStock.value - 1)
        listenSSE(res.data.ticket)
      }
    } catch (e: any) {
      result.value = {
        success: false,
        code: e.response?.data?.code || 'ERROR',
        message: e.response?.data?.detail || e.response?.data?.message || '抢购失败'
      }
    } finally {
      loading.value = false
    }
  }

  function listenSSE(ticket: string) {
    const es = new EventSource(`/api/seckill/sse/${ticket}/`)
    es.onmessage = (ev) => {
      const data = JSON.parse(ev.data)
      if (data.status === 'success') {
        orderNo.value = data.order_no
        result.value = {
          success: true,
          code: 'SUCCESS',
          ticket,
          message: data.message
        }
        es.close()
      } else if (data.status === 'failed') {
        result.value = {
          success: false,
          code: 'FAILED',
          ticket,
          message: data.message
        }
        es.close()
      }
    }
    es.onerror = () => es.close()
  }

  return { productId, remainingStock, loading, result, orderNo, fetchProduct, execute }
})
```

```typescript
    return () => es.close()
  }

  return { top, myRank, myScore, fetchTop, fetchMe, subscribeRealtime }
```

```python
    """秒杀开始前批量预热所有商品库存到 Redis"""
    from apps.products.models import Product
    r = get_redis()
    pipeline = r.pipeline()
    products = Product.objects.filter(is_seckill=True)
    for p in products:
        pipeline.set(f"seckill:stock:{p.id}", p.seckill_stock)
        pipeline.delete(f"seckill:bought:{p.id}")
        # 同时缓存商品详情
        pipeline.hset(
            f"product:detail:{p.id}",
            mapping={
                "name": p.name, "price": str(p.price),
                "seckill_price": str(p.seckill_price or p.price),
                "start_at": p.start_at.isoformat() if p.start_at else "",
            }
        )
        pipeline.expire(f"product:detail:{p.id}", 3600)
    results = pipeline.execute()
    return len(results)
```

### 7.2 热点 key 处理

```
热点 key 问题：
秒杀商品 ID 即热点 key，单节点 Redis 压力大

解决方案：
┌────────────────────────────────────────────────┐
│ 1. 本地缓存（多级缓存）                         │
│    Django 进程内 LRU 缓存 + Redis               │
│    设置 1-3 秒短 TTL，允许短时不一致             │
│                                                │
│ 2. key 分片                                    │
│    seckill:stock:1001 → seckill:stock:1001:0/1 │
│    客户端随机选一个分片扣减                       │
│    Lua 脚本聚合所有分片判断剩余                  │
│                                                │
│ 3. 读写分离                                     │
│    写主节点，读从节点                            │
│    Sentinel 模式 + preferredSlaves              │
│                                                │
│ 4. Cluster 分片                                │
│    用 {product:1001} hash tag                  │
│    确保相关 key 在同一槽                         │
└────────────────────────────────────────────────┘
```

`apps/seckill/sharded_stock.py`：

```python
# apps/seckill/sharded_stock.py
"""热点 key 分片实现：单 key 拆分为 N 个分片"""
import random

from apps.common.redis_client import get_redis

SHARD_COUNT = 10

def shard_keys(product_id: int) -> list[str]:
    return [f"seckill:stock:{product_id}:{i}" for i in range(SHARD_COUNT)]

def preheat_sharded(product_id: int, total_stock: int):
    """预热时将库存均匀分配到 N 个分片"""
    r = get_redis()
    per_shard = total_stock // SHARD_COUNT
    remainder = total_stock % SHARD_COUNT
    pipeline = r.pipeline()
    keys = shard_keys(product_id)
    for i, k in enumerate(keys):
        pipeline.set(k, per_shard + (1 if i < remainder else 0))
    pipeline.execute()

def deduct_sharded(product_id: int, user_id: int) -> bool:
    """随机选一个分片扣减，失败则尝试下一个"""
    r = get_redis()
    keys = shard_keys(product_id)
    random.shuffle(keys)
    for k in keys:
        # Lua 原子扣减（省略 bought 集成）
        stock = int(r.get(k) or 0)
        if stock > 0:
            new_stock = r.decr(k)
            if new_stock >= 0:
                return True
            # 并发回滚
            r.incr(k)
    return False

def get_total_remaining(product_id: int) -> int:
    r = get_redis()
    keys = shard_keys(product_id)
    pipeline = r.pipeline()
    for k in keys:
        pipeline.get(k)
    return sum(int(v or 0) for v in pipeline.execute())
```

## 十、典型踩坑表

| 问题 | 原因 | 解决 |
|------|------|------|
| 库存为 0 后仍能下单 | `DECR` 后未检查负数 | Lua 脚本先 `GET` 判断再 `DECR` |
| 重复下单 | 用户快速点击两次 | `SET NX EX` 防重 + bought 集合去重 |
| 订单丢失 | Stream 消费失败未重试 | `acks_late=True` + `XCLAIM` 超时回收 |
| SSE 无数据 | Nginx 缓冲开启 | `proxy_buffering off` + `chunked_transfer_encoding on` |
| 库存预热不生效 | 容器启动顺序错误 | depends_on healthcheck + 启动脚本调用 preheat |
| 雪崩：所有商品同时过期 | TTL 相同 | 预热时叠加随机抖动 |
| 击穿：热点 key 失效瞬间 | 高并发重建 | 分布式锁 + 永不过期 + 后台刷新 |
| 穿透：查询不存在商品 | 缓存空值 | 缓存空值 + 短 TTL + 布隆过滤器 |
| Celery 任务卡死 | `prefetch_multiplier=4` 抢占长任务 | 设为 1，配合 `acks_late` |
| Stream 内存溢出 | 未设置 MAXLEN | `XADD ... MAXLEN 100000 ~` |
| Redis 主从延迟读旧值 | 写主立即读从 | 关键读走主，或 Sentinel `role=master` |
| JWT 续签问题 | token 过期未刷新 | 配置 SimpleJWT refresh + 前端拦截器 |
| 大 V 发帖阻塞 | 同步推送到百万粉丝 | 大 V 走拉模式，普通用户走推模式 |
| 排行榜 ZSet 内存膨胀 | 历史数据未清理 | 定时 `ZREMRANGEBYRANK` 保留 Top N |
| 限流误杀正常用户 | 全局限流过严 | 用户级 + IP 级双重限流，分级配额 |
| Docker 容器时区错误 | 默认 UTC | `TZ=Asia/Shanghai` 环境变量 |

## 小思考题帮你巩固

1. **秒杀"不超卖"靠什么保证？只看 Redis `INCR` 库存够吗？**（提示：扣库存要用 Lua 原子"检查库存>0 再减"，避免读到负数/并发扣超；订单也要在 DB 侧校验唯一约束（防并发提交同单），见三后端实现。）
2. **"防重复下单"的分布式锁为什么锁值要用用户+订单标识（uuid）并且 Lua 释放？**（提示：裸 DEL 会误删别人的锁；业务结束要判断"还是我的锁"才删，见三 3.x 与 10 篇。）
3. **拍下即"预扣库存"，付款前取消/超时怎么回补库存？**（提示：订单状态机（created→paid/cancelled/timedout）；取消时 Lua 还原库存并幂等防重复回补，见三。）
4. **为什么订单处理用 Celery + Redis Stream 而不是同步请求里做完？"秒回 + 异步落库"好在哪里？**（提示：下单本身要快（秒杀）；支付/库存扣减/通知放消费组并行异步，前端轮询/SSE 拿结果，见三/08 篇 Stream。）
5. **SSE 与 WebSocket 在"排行榜实时推送"这个场景选谁？为什么？**（提示：排行榜是"服务端单向推"；SSE 天然单向 + 自动重连简单，WebSocket 是双向全双工（聊天/协作才需要）——单向上 SSE 更轻，见四前端实现。）

<summary>参考答案（点击展开）</summary>

1. 不够。`INCR` 只保证计数不超负数，但"读-判断-写"多命令在并发下会超扣。正确做法是 Lua 一把锁脚本里：`local n=redis.call('GET',...); if n>0 then DECR ... return 1 else return 0`，原子检查+扣减保证不超卖；订单本身再在 DB 加唯一约束兜底（防止同一用户同商品重复下单），双保险。
2. 防重复下单的锁 key 用"用户+商品/订单标识"，value 存本次请求的 uuid；释放用 Lua `if GET==uuid then DEL`——只有本人能释放自己的锁，避免"业务超时后别人的锁被误删"（见 10 篇 1.2 缺陷 2）。业务内还会再次校验订单是否已存在（幂等）。
3. 预扣后订单进入"待付款"；取消或超过支付超时（如 15 分钟）时触发"回补库存"任务，用 Lua 原子 `INCR` 并记录"本次释放的唯一事件 ID"防重复回补（幂等）。回补与扣减走同一把库存锁，保证最终一致。
4. "拍下即返回成功、后台排队处理"把下单主路径压到几十 ms——清算/支付/通知都是可异步的耗时长尾。Celery + Redis Stream 消费组提供"至少一次 + ACK/重投/死信"，前端用 SSE/轮询拿订单最终状态；同步处理的话高并发秒杀会被长尾任务阻塞（见 08 篇 Stream）。
5. 选 SSE：排行榜就是"服务端→浏览器单向推"，SSE 基于 HTTP 单向流、自带自动重连与事件类型，实现简单；WebSocket 是全双工（双向随时随地互发）——聊天/协同编辑才需要。单向推送用 SSE、双向交互用 WebSocket，避免为排行榜引入全套 WS 基建。

## 本章小结

1. 架构选型：Django + DRF + Celery + Redis + MySQL + Vue3 是电商秒杀的成熟组合，Redis 同时承担缓存、锁、队列、排行榜、会话五种角色。
2. 库存预扣必须用 Lua 脚本（`GET` 判断 + `DECR` 原子），切勿用 `DECR` 后再判断负数（并发下会超卖）。
3. 异步订单处理走 Redis Stream 消费者组，配合 `acks_late=True` + `XCLAIM` 超时回收，保证至少一次消费。
4. 排行榜用 ZSet，`ZADD/ZINCRBY` 写入、`ZREVRANGE` 读取，毫秒级响应；日榜/周榜用 `ZUNIONSTORE` 合并。
5. Feed 流采用推拉结合：普通用户发帖推到粉丝 inbox（写扩散），大 V 仅写 outbox（读扩散时合并），平衡写读开销。
6. SSE 实时推送必须配置 Nginx `proxy_buffering off` + `chunked_transfer_encoding on`，否则数据被缓冲导致延迟。
7. 容器化部署用单一 `docker-compose.yml` 整合 9 个服务（mysql/redis/backend/worker/beat/frontend/nginx/exporter/prometheus/grafana），一键 `docker compose up -d` 即可启动全栈。
8. 性能优化三板斧：Pipeline 批量、连接池复用、热点 key 分片；缓存防雪崩加随机 TTL 抖动，防击穿用分布式锁，防穿透缓存空值 + 布隆过滤器。
