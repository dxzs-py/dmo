## 一、为什么要有这套手册

大模型微调领域当前存在三大痛点：

1. **资料碎片化**：LoRA/QLoRA 原理散落在论文与博客中，PyTorch/HuggingFace/vLLM 框架各自有官方文档，但缺乏一条贯穿"原理→框架→实战→部署"的主线
2. **硬件门槛模糊**：多数教程默认 A100 80GB 环境，对消费级显卡（如 RTX 5070 8GB）的可行性分析与配置建议严重不足
3. **理论与实践脱节**：原理文章不给可运行代码，实战文章不讲数学直觉

本手册针对以上痛点，以 **RTX 5070 8GB 显卡** 为基准硬件，以 **PyTorch / Hugging Face / Ollama / vLLM** 为核心技术栈，系统化覆盖从 LoRA/QLoRA 数学原理到生产部署的完整路径。

## 二、硬件适配说明：RTX 5070 8GB

### 2.1 硬件能力边界

| 任务 | 可行性 | 配置要点 |
|------|--------|---------|
| 7B 模型 QLoRA 微调 | ✅ 可行 | NF4 量化 + batch=1 + 梯度检查点 + max_seq=1024，约 5.5GB 显存 |
| 7B 模型 LoRA 微调（FP16） | ❌ 不可行 | 需 ~16GB 显存，超出 8GB |
| 7B 模型推理（GGUF Q4） | ✅ 可行 | 约 4GB 显存，Ollama 推荐 |
| 3B 模型 QLoRA 微调 | ✅ 宽松 | 约 2.5GB 显存，可用更大 batch 与序列长度 |
| 14B+ 模型微调 | ❌ 不可行 | 需升级硬件或使用云 GPU |

### 2.2 8GB 显卡的"五条铁律"

1. **必须 QLoRA**：4bit NF4 量化 + 双重量化，模型权重从 14GB 压到 3.5GB
2. **batch_size=1**：用梯度累积（accumulation_steps=32）等效 batch=32
3. **gradient_checkpointing=True**：用 ~25% 训练时间换 60-70% 显存
4. **max_seq_length ≤ 1024**：长序列显存按 O(N) 增长，2048 即可能 OOM
5. **target_modules 精简**：8GB 下建议 `["q_proj","v_proj"]` 起步，效果不够再加 4 个

📖 详细配置见 [09_QLoRA微调7B实战_8GB完整流程.md](./09_QLoRA微调7B实战_8GB完整流程.md)
