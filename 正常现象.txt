# 正常现象记录（代理模式基准）

> 目标：以聊天模块「代理模式」为基准，记录其全部展示细节（消息渲染、工具卡片顺序、审批、子代理、wait 卡等），
> 供深度研究模式逐项对齐。

## 测试环境
- 页面 11：/chat 代理模式（触发端）
- 页面 12：/chat 代理模式（同步观察端）
- 任务：「并行派发 2 个子代理：子代理 1 运行 ollama list，子代理 2 运行 ollama ps。等两个子代理都完成后，汇总它们的结果给我」
- 发送前已选 14 个工具（含 spawn_sub_agent / wait_for_subagent / shell_exec / todo_write / write_file）

## 效果细节（页面 12 观察，页面 11 一致）

### 1. 消息与工具卡内联顺序（正文 + 工具卡切段）
AI 消息结构（按顺序）：
1. 正文段：「我来并行派发两个子代理分别执行 ollama list 和 ollama ps，然后等待它们完成。」
2. spawn_sub_agent 卡（子代理 1，ollama-list-runner）：已完成，含输入参数（task/tools/agentName）
3. 子代理卡「子代理 1 · L1」：显示「等待你的确认 · 共 1 项待审批」（子代理内部 shell_exec 审批，需点击展开）
4. spawn_sub_agent 卡（子代理 2，ollama-ps-runner）：已完成
5. 子代理卡「子代理 2 · L1」：同样「等待你的确认 · 共 1 项待审批」
6. 正文段：「两个子代理已并行启动：\n🔹 ollama-list-runer（thread: ...）→ 执行 ollama list\n🔹 ollama-ps-runer（thread: ...）→ 执行 ollama ps\n\n现在等待两个子代理全部完成」
7. **wait_for_subagent 卡：状态「等待中」**（立即出现，位于正文「现在等待两个子代理全部完成」之后，位置正确）
   - 参数：{"subagentThreadIds": ["subagent_...", "subagent_..."]}
   - 显示「复制」「删除」操作

### 2. 关键结论
- wait_for_subagent 卡在等待期间**立即出现**，状态显示「等待中」，位置紧跟正文末尾。
- spawn 卡在正文内联位置（正文切段处）出现，两个 spawn 并列，子代理卡紧跟在各自 spawn 卡之后。
- 工具卡顺序 = 时间顺序（正文 → spawn1 → spawn2 → 正文 → wait）。
- 子代理内部工具审批需点击子代理卡展开可见。

### 3. 子代理内部审批展开效果（点击「等待你的确认」）
子代理卡展开后，内部显示 shell_exec 审批卡：
- 路径展示：`main → ollama-list-runner → ollama-list-runner L1`
- 风险：高危；状态：待审批
- 输入参数：`ollama list`（显示 command 字段）
- 审批确认面板：标题「确认执行 shell_exec」+「Agent 请求执行 shell_exec」，参数明细 command: ollama list，按钮「拒绝 / 确认执行」

### 4. 代理模式完整流程细节（重点：spawn 顺序 / 子代理卡顺序 / wait 位置）

**最终消息结构（按渲染顺序，页面 11/12 一致）：**

```
正文①：「我来并行派发两个子代理分别执行 ollama list 和 ollama ps，然后等待它们完成。」
spawn_sub_agent 卡①（子代理 1，ollama-list-runner）→ 已完成
  子代理卡①「子代理 1 · L1」：→ 已完成 → 点击展开详情 → 结果 markdown（✅ 命令执行成功 + 模型清单表格）
spawn_sub_agent 卡②（子代理 2，ollama-ps-runner）→ 已完成
  子代理卡②「子代理 2 · L1」：→ 已完成（执行前为「等待你的确认 · 共 1 项待审批」，展开内部为 shell_exec 审批卡）
正文②：「两个子代理已并行启动：🔹 ... 🔹 ...\n\n现在等待两个子代理全部完成」
wait_for_subagent 卡：等待中 → 已完成（结果 = 子代理结果摘要）
正文③（汇总）：「1️⃣ ollama list ... 2️⃣ ollama ps ... 🔍 关键结论 ...」
```

**关键观察（正常现象基准）：**
1. **创建子代理顺序**：spawn_sub_agent 卡按 LLM 工具调用生成顺序（seq）内联在正文切段处，两个 spawn 并列。
2. **子代理卡顺序**：每个子代理卡**紧跟其对应 spawn 卡之后**（spawn1→子代理卡1→spawn2→子代理卡2），不是集中堆在末尾。
3. **wait_for_subagent 位置**：位于正文②「现在等待两个子代理全部完成」**之后**（正文末尾切段处），**立即出现**，状态「等待中」。
4. **wait 卡状态流转**：等待中（等待子代理）→ 已完成（子代理全部完成，结果填充）。
5. **子代理审批**：子代理内部 shell_exec 需展开子代理卡才可见；审批卡路径展示 `main → ollama-list-runner → ollama-list-runner L1`。
6. **最终汇总**：wait 卡之后的正文③为最终汇总（子代理结果 + 结论）。
7. 子代理卡内结果 markdown（表格、代码块）渲染正常。
8. 消息尾部操作：「复制 / 重新生成 / 删除」，建议追问（💡）。
