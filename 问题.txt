### 问题F：chat 模块子代理内部工具审批创建失败（缺 chat_session_id）→ 子代理挂起无审批按钮 ✅ 已修复（待重启复测）
- 现象：chat 代理模式输入"运行 ollama list … 尽量通过子代理完成任务"，主代理 spawn_sub_agent 审批通过后子代理启动，子代理内部 shell_exec（ollama list）审批创建失败：
  `ERROR [ApprovalService] chat 模块审批缺少 chat_session_id，拒绝创建: interrupt_id=call_00_lea56srIbvZmc0zPzW3v5596, source_id=<chat_session_id>`
  `ERROR [ResearchApproval] 创建审批 DB 记录失败`
- 前端表现：子代理卡片展开详情内 shell_exec 显示"等待中"，无"确认执行/拒绝"审批控件；子代理挂起（interrupted_pending_user_input），任务卡住
- 根因：configurable 源头契约只有 research 链路实现（research_runner.execute_research_async 构建时写入 chat_session_id/assistant_message_id），**chat 代理模式（chat_service.py）构建主会话 configurable 时未写入** → spawn 工具原样继承 → 子代理 configurable 缺 chat_session_id → langgraph_adapter._create_approvals_from_interrupts 取到 None → source=chat 时 request_approval_async 强制校验失败拒绝创建
- 修复（源头统一契约，无兜底补丁）：
  1. `apps/chat/services/chat_service.py`（L1128-1133）：构建主会话 configurable 时写入 `chat_session_id=_sub_session_id`、`assistant_message_id=_sub_message_id`，与 research_runner L345-350 模式对齐
  2. `ai_engine/subagent_runtime/adapters/langgraph_adapter.py`：恢复直接从 configurable 读取（无 parent_thread_id 兜底），并补注释说明各模块源头契约
- 状态：待重启复测（chat 代理模式 → 子代理 shell_exec 审批控件应出现）
- 复测结果（2026-08-16 20:29 会话）：✅ 修复生效——spawn 审批通过后，子代理内部 shell_exec/file_reader/fs_write_file 审批控件全部正常出现并逐一通过执行，任务完整走完（ollama list → ollama run ornith:latest "你是谁" → ollama ps → file_reader 预读 → fs_write_file 写入 → file_reader 验证），test_approval.txt 成功写入 2961 字节报告，两浏览器实时同步一致

### 问题G：子代理最终报告在详情卡片内重复显示两次 ✅ 已修复（待重启复测）
- 现象：子代理完成后，详情卡片内出现两份完全相同的"📋 执行结果汇总"报告（页面15 uid=200_18~85 与 200_88~155 内容一致，浏览器16 同样重复）。第一份结尾多一个孤立 "✅ "。主消息流中主代理未输出任何总结
- 根因（与问题H同根）：`SubAgentContentMiddleware.aafter_model`（subagent_support.py）每次模型调用后**无条件转发最后一条 AIMessage 的完整 content**。子代理每次工具审批 interrupt → 用户确认 → Command(resume) 恢复时，LangGraph **重放节点**，aafter_model 对**同一条 AIMessage 再次触发** → 同段文本重复推送；前端 `_applySubagentContent` 纯追加（entry.content += content）→ 重复显示。本次会话子代理共 6 次审批，每轮中间文本均重复
- 修复（消息级幂等，与 tool_event_extractor 的 seen_tool_call_ids 惯例一致）：
  1. `subagent_support.py`：middleware 转发时携带 `msg_id`（AIMessage.id，缺失时用 content 确定性哈希）
  2. `chat_service.py` `_on_subagent_content`：闭包内 `_sent_subagent_msg_keys`（subagent_thread_id → set）按 msg_id 去重，重放消息跳过（闭包随回调对象跨 resume 持续存在）
  3. `research/services/adapter.py` `_on_subagent_content`：同构幂等（self._sent_subagent_msg_keys），chat/research 统一能力

### 问题I：chat 模式 wait_for_subagent 挂起后永不恢复（主代理收不到子代理结果）✅ 已修复（待重启复测）
- 现象：子代理完成后 wait_for_subagent 卡"等待中"，主代理无最终总结，子代理卡片停"执行中"
- 决定性日志：`20:33:10,774 子代理执行完成: subagent_6d523f9b4d0f4752, result_len=1350` + `20:33:10,775 lifecycle 60 无父 Graph 等待子代理（已收尾或未注册）`
- 根因：wait 挂起/唤醒链路只在 research 实现（adapter.py subagent_wait_suspend + SessionExecutor._handle_suspend/_resume_after_subagent_wait），**chat 链路四处全缺**：
  1. `loop.py run_stream_loop` 只处理审批 interrupt（_collect_chat_approvals），wait interrupt 被忽略 → 主代理协程直接结束
  2. chat 从未注册 parent awaiter → 子代理完成时 lifecycle 找不到唤醒回调
  3. chat 恢复路径（Command(resume) 重入）不存在
  4. chat_service.run_agent_session 开头的"pending interrupt 自动拒绝"清理会误拒恢复场景的 wait interrupt
- 修复（chat 与 research 同构，spec D4 统一能力）：
  1. `loop.py`：新增 `_detect_subagent_wait_suspend`（复用 is_subagent_wait_interrupt）→ 写入 `data["_subagent_wait_suspend"]` 后退出流（不 resume）
  2. `chat_service.py`：run_agent_session 挂起时返回挂起 dict（不发 context/end、不更新 tokens）+ 跳过 finalize_stream；新增 resume_command 恢复模式（graph_input=Command(resume)，跳过 pending interrupt 自动拒绝）
  3. `chat_executor_core.py`：挂起时调用 `executor._handle_chat_wait_suspend`，finally 条件跳过 finalize/checkpointer 释放
  4. `session_executor.py`：新增 `_handle_chat_wait_suspend`（置挂起态+竞态二次检查+注册 awaiter，与 research _handle_suspend 同构）；`_resume_after_subagent_wait` 按 session_type 分派（chat→params 注入 resume_command 重跑 _run_chat；research→原逻辑）；chat 恢复失败广播 STREAM_COMPLETED(success=False)（不用 research 专属 _handle_failure）
- 验证：py_compile 全部通过；test_subagent_nesting.py + test_subagent_wait.py 26 passed；apps/chat 15 passed
